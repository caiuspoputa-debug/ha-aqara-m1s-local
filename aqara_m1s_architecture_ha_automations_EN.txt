Aqara M1S – Final Architecture: HomeKit + Local Integration + Automations
========================================================================

Purpose:
- define the responsibilities of HomeKit and the local integration;
- document the confirmed functions;
- avoid commands that may freeze or destabilize the hub;
- document sound playback and the required WAV format;
- maintain a stable and easy-to-manage architecture.


============================================================
1. Recommended architecture
============================================================

HomeKit can remain responsible for:

- alarm_control_panel;
- arming and disarming;
- Home, Away, and Night states;
- the hub's official volume;
- the hub light, when existing automations already use HomeKit entities;
- pairing and identify.

The Aqara M1S Local integration can manage:

- playback of internal sounds;
- playback of custom WAV sounds;
- buttons for files from music-ch;
- buttons for files from music-us;
- buttons for files from music-scene;
- playback volume control for local sounds;
- local LED control;
- information and diagnostics available through Telnet;
- confirmed local sensors;
- the local MQTT connection;
- the persistent Telnet connection.

It is not necessary to move every function into a single integration.

Existing HomeKit automations can remain unchanged, while the local integration
can be used for additional functions.

Aqara M1S Local v0.4.6

4. Official hub volume
============================================================

The official volume is managed internally through:

basis.system/system_volume

Main process involved:

mha_basis

Associated internal property:

persist.sys.volume

In HomeKit, official volume is exposed through:

siid = 5
piid = 2

The corresponding Home Assistant entities may be:

number.aqarahublight_volume
number.aqara_hub_m1s_2653_volume


============================================================
5. Local playback volume
============================================================

The local integration exposes:

Sound Playback Volume

Range:

1–100

The value is passed directly to the official playback command:

/bin/basis_cli -sys -s doorbell 99 0 <volume>

Example:

/bin/basis_cli -sys -s doorbell 99 0 30

This method respects volume and uses the official route:

basis_cli
→ basis.system/system_sing
→ mha_basis

aplay is no longer used for normal sound playback from the integration.

aplay bypasses official volume control and should not be used for the main
playback buttons.


============================================================
6. Internal sound playback
============================================================

Confirmed official command:

/bin/basis_cli -sys -s <type> <index> <duration> <volume>

Confirmed types:

alarm
doorbell
welcome

Example:

/bin/basis_cli -sys -s doorbell 1 0 30

Parameters:

type       = alarm, doorbell, or welcome
index      = sound number
duration   = 0 for one-time playback
volume     = 1–100


============================================================
7. Custom WAV playback
============================================================

Slot reserved for the integration:

/data/musics/music-scene/door_bell_99.wav

The integration no longer copies the WAV file before every playback.

It uses a symbolic link:

ln -sf <source_file> \
/data/musics/music-scene/door_bell_99.wav

Then it runs:

/bin/basis_cli -sys -s doorbell 99 0 <volume>

Complete example:

ln -sf /data/musics/music-ch/add_sensor.wav \
/data/musics/music-scene/door_bell_99.wav \
&& /bin/basis_cli -sys -s doorbell 99 0 30

Advantages:

- almost instant playback;
- no repeated file copying;
- controllable volume;
- all sounds use the official mha_basis playback route.


============================================================
8. Confirmed WAV format
============================================================

The format reported by the hub for:

/data/musics/music-ch/add_sensor.wav

is:

format       : S32_LE
channels     : 1
rate         : 32000
exact rate   : 32000
msbits       : 32

Recommended format for custom sounds:

- PCM WAV;
- signed 32-bit little-endian;
- mono;
- 32000 Hz;
- 32-bit.

FFmpeg example:

ffmpeg -i input.mp3 \
-ac 1 \
-ar 32000 \
-c:a pcm_s32le \
output.wav

============================================================
10. Transferring files from Windows
============================================================

The hub does not provide SSH on port 22.

scp does not work:

ssh: connect to host 192.168.0.100 port 22: Connection refused

File transfer is performed temporarily with BusyBox nc.

On the hub:

nc -l -p 12345 > /destination/path/file.wav

Example:

nc -l -p 12345 > \
/data/musics/music-ch/add_sensor_original.wav

On Windows PowerShell:

$client = New-Object System.Net.Sockets.TcpClient(
  "192.168.0.100",
  12345
)

$stream = $client.GetStream()

$bytes = [System.IO.File]::ReadAllBytes(
  "C:\path\file.wav"
)

$stream.Write($bytes, 0, $bytes.Length)
$stream.Close()
$client.Close()

After the transfer, verify the file size on the hub:

ls -l /data/musics/music-ch/file.wav


============================================================
11. Backup before replacing a sound
============================================================

Before replacing an original file:

cp file.wav file_original.wav

Example:

cp /data/musics/music-ch/add_sensor.wav \
/data/musics/music-ch/add_sensor_original.wav

Always verify that the backup exists before overwriting the original file.

============================================================
13. Trigger, action, and entity
============================================================

Trigger:

Starts the automation.

Example:

triggers:
  - entity_id: binary_sensor.senzor_de_contact_1_water_leak
    from: "off"
    to: "on"
    trigger: state

Action:

Represents the operations executed after the trigger:

- changing the volume;
- playing a sound;
- starting the alarm;
- changing the LED color;
- restoring a scene.

Entity:

The Home Assistant device or object used in a trigger or action.

16. Light snapshot
============================================================

Creating the snapshot:

- data:
    scene_id: snapshot_bec
    snapshot_entities:
      - light.aqarahublight_lightbulb
  action: scene.create

Restoring the snapshot:

- continue_on_error: true
  target:
    entity_id: scene.snapshot_bec
  action: scene.turn_on

For two hubs:

snapshot_entities:
  - light.aqarahublight_lightbulb
  - light.aqara_hub_m1s_2653_lightbulb

Do not remove existing snapshot scenes from automations.

============================================================
19. Local MQTT
============================================================

The internal Mosquitto broker runs on:

127.0.0.1:1883

The LAN tunnel is exposed on:

192.168.0.100:1884

Script:

/data/scripts/mqtt_tunnel.sh

Expected processes:

nc -l -p 1884
nc 127.0.0.1 1883

The tunnel effectively supports one LAN client at a time.

If the tunnel remains occupied after a Home Assistant reload:

killall nc

Warning:

Use this command only when no active file transfer is running through nc.

The tunnel script should automatically restart the required processes.

============================================================
22. Illuminance / lux
============================================================

The hub sends a local raw value through MQTT:

topic:

zigbee/send

did:

lumi.0

resource:

0.3.85

The value reacts to lighting changes, but it has not been confirmed as a
precise physical lux measurement.

It can be described as:

Raw illuminance

or:

Raw light level

It should not be presented as a calibrated and verified lux value.

If exposed in Home Assistant, the name and description should clearly state
that it is a raw value.

============================================================
24. Safety rules
============================================================

Do not stop:

mha_basis
mha_master
homekitserver
miio_client

Do not reboot the hub for every test.

Do not run simultaneously:

- the MQTT tunnel through nc;
- file transfer through the same port;
- multiple LAN clients on the MQTT tunnel.

Before running killall nc, verify that no file transfer is active.

Create a backup before replacing original files.

Test one modification at a time.

Verify the file size after every transfer.


============================================================
25. Rules for modifying automations
============================================================

Do not remove volume blocks when they contain day/night logic.

Do not change trigger sensors unless explicitly requested.

Do not switch entities between hubs unless explicitly requested.

Do not delete existing snapshot scenes.

Do not convert dual-hub automations into single-hub automations unless
explicitly requested.

Do not rename entities already used in automations.

For custom sounds, preserve the original filename so the Home Assistant
entity_id remains unchanged.
