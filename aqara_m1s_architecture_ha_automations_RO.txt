Aqara M1S – Arhitectura finală: HomeKit + integrare locală + automatizări
========================================================================

Scop:
- stabilirea responsabilităților HomeKit și ale integrării locale;
- documentarea funcțiilor confirmate;
- evitarea comenzilor care pot bloca hubul;
- documentarea redării sunetelor și a formatului WAV;
- păstrarea unei arhitecturi stabile și ușor de întreținut.


============================================================
1. Arhitectura recomandată
============================================================

HomeKit poate rămâne responsabil pentru:

- alarm_control_panel;
- armare și dezarmare;
- stările Home, Away și Night;
- volumul oficial al hubului;
- lumina hubului, când automatizările existente folosesc deja entitățile HomeKit;
- pairing și identify.

Integrarea locală Aqara M1S Local poate gestiona:

- redarea sunetelor interne;
- redarea sunetelor WAV personalizate;
- butoanele pentru fișierele din music-ch;
- butoanele pentru fișierele din music-us;
- butoanele pentru fișierele din music-scene;
- controlul volumului folosit la redarea locală;
- controlul local al LED-ului;
- informațiile și diagnosticarea disponibile prin Telnet;
- senzorii locali confirmați;
- conexiunea MQTT locală;
- conexiunea Telnet persistentă.

Nu este necesar ca toate funcțiile să fie mutate într-o singură integrare.

Automatizările HomeKit existente pot rămâne neschimbate, iar integrarea
locală poate fi folosită pentru funcțiile suplimentare.

============================================================
4. Volumul oficial al hubului
============================================================

Volumul oficial este gestionat intern prin:

basis.system/system_volume

Procesul principal implicat:

mha_basis

Proprietatea internă asociată:

persist.sys.volume

În HomeKit, volumul oficial este expus prin:

siid = 5
piid = 2

Entitățile Home Assistant corespunzătoare pot fi:

number.aqarahublight_volume
number.aqara_hub_m1s_2653_volume


============================================================
5. Volumul redării locale
============================================================

Integrarea locală expune:

Sound Playback Volume

Interval:

1–100

Valoarea este transmisă direct comenzii oficiale de redare:

/bin/basis_cli -sys -s doorbell 99 0 <volum>

Exemplu:

/bin/basis_cli -sys -s doorbell 99 0 30

Această metodă respectă volumul și folosește ruta oficială:

basis_cli
→ basis.system/system_sing
→ mha_basis

Nu se mai folosește aplay pentru redarea normală a sunetelor din integrare.

aplay ocolește controlul oficial al volumului și nu trebuie folosit pentru
butoanele principale de redare.


============================================================
6. Redarea sunetelor interne
============================================================

Comanda oficială confirmată:

/bin/basis_cli -sys -s <tip> <index> <durată> <volum>

Tipuri confirmate:

alarm
doorbell
welcome

Exemplu:

/bin/basis_cli -sys -s doorbell 1 0 30

Parametri:

tip      = alarm, doorbell sau welcome
index    = numărul sunetului
durată   = 0 pentru o singură redare
volum    = 1–100


============================================================
7. Redarea fișierelor WAV personalizate
============================================================

Slot rezervat integrării:

/data/musics/music-scene/door_bell_99.wav

Integrarea nu mai copiază fișierul WAV la fiecare redare.

Folosește un link simbolic:

ln -sf <fișier_sursă> \
/data/musics/music-scene/door_bell_99.wav

Apoi rulează:

/bin/basis_cli -sys -s doorbell 99 0 <volum>

Exemplu complet:

ln -sf /data/musics/music-ch/add_sensor.wav \
/data/musics/music-scene/door_bell_99.wav \
&& /bin/basis_cli -sys -s doorbell 99 0 30

Avantaje:

- redare aproape instant;
- fără copiere repetată a fișierelor;
- volum controlabil;
- toate sunetele folosesc ruta oficială mha_basis.


============================================================
8. Formatul WAV confirmat
============================================================

Formatul raportat de hub pentru:

/data/musics/music-ch/add_sensor.wav

este:

format       : S32_LE
channels     : 1
rate         : 32000
exact rate   : 32000
msbits       : 32

Format recomandat pentru sunetele personalizate:

- WAV PCM;
- signed 32-bit little-endian;
- mono;
- 32000 Hz;
- 32 biți.

Exemplu FFmpeg:

ffmpeg -i input.mp3 \
-ac 1 \
-ar 32000 \
-c:a pcm_s32le \
output.wav

============================================================
10. Transferul fișierelor de pe Windows
============================================================

Hubul nu oferă SSH pe portul 22.

scp nu funcționează:

ssh: connect to host 192.168.0.100 port 22: Connection refused

Transferul se face temporar cu BusyBox nc.

Pe hub:

nc -l -p 12345 > /cale/destinatie/fisier.wav

Exemplu:

nc -l -p 12345 > \
/data/musics/music-ch/add_sensor_original.wav

Pe Windows PowerShell:

$client = New-Object System.Net.Sockets.TcpClient(
  "192.168.0.100",
  12345
)

$stream = $client.GetStream()

$bytes = [System.IO.File]::ReadAllBytes(
  "C:\cale\fisier.wav"
)

$stream.Write($bytes, 0, $bytes.Length)
$stream.Close()
$client.Close()

După transfer, dimensiunea trebuie verificată pe hub:

ls -l /data/musics/music-ch/fisier.wav


============================================================
11. Backup înainte de înlocuirea unui sunet
============================================================

Înainte de înlocuirea unui fișier original:

cp fisier.wav fisier_original.wav

Exemplu:

cp /data/musics/music-ch/add_sensor.wav \
/data/musics/music-ch/add_sensor_original.wav

Se verifică întotdeauna existența backupului înainte de suprascriere.


============================================================
12. Automatizări de volum zi/noapte
============================================================

Exemplu: volum 20 noaptea și 60 ziua:

value: >-
  {% if now().hour >= 21 or now().hour < 9 %}
    20
  {% else %}
    60
  {% endif %}

Exemplu: volum 5 noaptea și 25 ziua:

value: >-
  {% if now().hour >= 21 or now().hour < 8 %}
    5
  {% else %}
    25
  {% endif %}

Nu se elimină blocurile de volum dacă includ logică zi/noapte.


============================================================
13. Trigger, action și entity
============================================================

Trigger:

Pornește automatizarea.

Exemplu:

triggers:
  - entity_id: binary_sensor.senzor_de_contact_1_water_leak
    from: "off"
    to: "on"
    trigger: state

Action:

Reprezintă operațiile executate după trigger:

- schimbarea volumului;
- redarea unui sunet;
- pornirea alarmei;
- schimbarea culorii LED-ului;
- restaurarea scenei.

Entity:

Dispozitivul sau obiectul Home Assistant folosit în trigger sau action.

14. Lumina hubului

Exemplu de payload:

    "breath": 500,
    "green": 105,
    "red": 245

  "id": 50001,

Entitățile HomeKit pot fi folosite în continuare în automatizările existente:

16. Snapshot pentru lumină
============================================================

Crearea snapshotului:

- data:
    scene_id: snapshot_bec
    snapshot_entities:
      - light.aqarahublight_lightbulb
  action: scene.create

Restaurarea:

- continue_on_error: true
  target:
    entity_id: scene.snapshot_bec
  action: scene.turn_on

Pentru două huburi:

snapshot_entities:
  - light.aqarahublight_lightbulb
  - light.aqara_hub_m1s_2653_lightbulb

Nu se șterg scenele snapshot din automatizările existente.

============================================================
18. Pairing și identify
============================================================

Identify folosește intern:

local.identify_dev
→ basis.system/system_identify

Pairing Zigbee folosește:

miIO.zb_start_provision

cu durată observată:

59 secunde

Închiderea pairingului:

miIO.zb_end_provision

Resursa:

8.0.2109

este asociată ferestrei de pairing, nu volumului.


============================================================
19. MQTT local
============================================================

Brokerul Mosquitto rulează intern pe:

127.0.0.1:1883

Tunelul LAN este expus pe:

192.168.0.100:1884

Script:

/data/scripts/mqtt_tunnel.sh

Procese așteptate:

nc -l -p 1884
nc 127.0.0.1 1883

Tunelul acceptă practic un singur client LAN simultan.

Dacă tunelul rămâne blocat după reload Home Assistant:

killall nc

Atenție:

Această comandă trebuie folosită numai când nu există un transfer de fișiere
activ prin nc.

Scriptul tunelului trebuie să repornească automat procesele necesare.

============================================================
22. Illuminance / lux
============================================================

Hubul trimite local o valoare brută prin MQTT:

topic:

zigbee/send

did:

lumi.0

resource:

0.3.85

Valoarea răspunde la schimbările de lumină, dar nu este confirmată ca o
măsurătoare fizică precisă în lux.

Poate fi descrisă ca:

Raw illuminance
sau
Raw light level

Nu trebuie prezentată drept valoare calibrată și verificată în lux.

Dacă este expusă în Home Assistant, numele și descrierea trebuie să precizeze
că este o valoare brută.

============================================================
24. Reguli de siguranță
============================================================

Nu se opresc:

mha_basis
mha_master
homekitserver
miio_client

Nu se repornește hubul pentru fiecare test.

Nu se rulează simultan:

- tunel MQTT prin nc;
- transfer de fișiere prin același port;
- mai mulți clienți LAN pe tunelul MQTT.

Înainte de killall nc se verifică dacă există un transfer activ.

Se face backup înainte de înlocuirea fișierelor originale.

Se testează câte o singură modificare.

Se verifică dimensiunea fișierului după transfer.


============================================================
25. Reguli pentru modificarea automatizărilor
============================================================

Nu se elimină blocurile de volum dacă au logică zi/noapte.

Nu se schimbă senzorii trigger fără cerere explicită.

Nu se schimbă entitățile între huburi fără cerere explicită.

Nu se șterg scenele snapshot existente.

Nu se transformă automatizările dual-hub în single-hub fără cerere explicită.

Nu se redenumesc entitățile folosite deja în automatizări.

Pentru sunetele personalizate se păstrează numele fișierului original,
astfel încât entity_id-ul Home Assistant să rămână neschimbat.
