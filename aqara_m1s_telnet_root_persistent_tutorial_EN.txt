# Aqara Hub M1S – Telnet persistent, Zigbee PA 0 și tunel MQTT permanent

## 1. Scop

Această procedură configurează un Aqara Hub M1S astfel încât, după fiecare reboot:

- firmware-ul original Aqara să pornească normal;
- Wi-Fi, HomeKit și serviciile locale să rămână funcționale;
- Telnet/root să fie activat automat;
- parametrul Zigbee Power Amplifier să fie setat automat la `0`;
- brokerul MQTT intern de pe `127.0.0.1:1883` să fie accesibil în LAN prin portul `1884`;
- tunelul MQTT să se refacă automat după deconectarea clientului;
- funcțiile locale importante, inclusiv lumina, sunetul și senzorul de iluminare, să rămână active.

Nu este necesar firmware modificat și nu se scrie nimic în rootfs.

---

## 2. Configurație testată

- Dispozitiv: Aqara Hub M1S
- Model: `lumi.gateway.aeu01`
- Firmware: `3.1.3_0009`
- Kernel: Linux 3.10.90, MIPS
- Cip Zigbee: NXP JN5189
- Interfață Zigbee: `/dev/ttyS1`
- Broker MQTT intern: `127.0.0.1:1883`
- Port MQTT expus în LAN: `1884`
- Serviciu Zigbee: `mzigbee_agent`
- Monitor servicii: `app_monitor.sh`

---

## 3. Avertismente importante

1. Nu modifica `/etc/init.d/rcS`.
2. Nu modifica `/bin/fw_manager.sh`.
3. Nu folosi `telnetd -l /bin/sh` ca metodă permanentă.
4. Scriptul `/data/scripts/post_init.sh` trebuie să pornească obligatoriu:
   ```sh
   fw_manager.sh -r &
   ```
5. Nu opri:
   - `mha_basis`
   - `mha_master`
   - `homekitserver`
   - `miio_client`
   - `mzigbee_agent`
   - `app_monitor.sh`
6. Nu expune portul `1884` pe Internet.
7. Telnet și MQTT sunt necriptate și trebuie folosite doar într-o rețea locală de încredere.
8. Ideal, primul test se face cu acces UART disponibil pentru recuperare.

---

## 4. De ce nu mai oprim `mzigbee_agent`

Metoda veche oprea:

```sh
killall app_monitor.sh
killall mzigbee_agent
```

Aceasta nu mai este recomandată.

Motivul: `mzigbee_agent` nu gestionează doar radio-ul Zigbee. Din testele făcute, el participă și la funcții locale ale hubului, inclusiv:

- controlul LED-ului;
- raportarea senzorului intern de iluminare;
- comunicația internă MQTT;
- alte funcții legate de hub.

Oprirea completă a procesului poate duce la pierderea controlului luminii și a altor funcții locale.

Metoda nouă păstrează serviciile active și execută doar:

```sh
zigbee_msnger set_pa 0
```

Aceasta setează parametrul Power Amplifier la `0`, fără să oprească întregul serviciu Zigbee.

Important: `zigbee_pa:0` nu dovedește că întregul radio JN5189 este complet oprit. Confirmă doar că parametrul PA este `0`, ceea ce dezactivează sau reduce amplificatorul RF extern.

## 5. Obținerea IP-ului și tokenului MiIO

Ai nevoie de:

- IP-ul hubului;
- tokenul MiIO.

Exemplu:

```text

```

În Windows PowerShell:

```powershell

```

Dacă sunt afișate modelul și versiunea firmware, tokenul este valid.

În Windows PowerShell sau CMD:

```powershell
python -m miio.cli device --ip 192.168.0.100 --token TOKEN raw_command set_ip_info "{\"ssid\":\"\\\"\\\"\",\"pswd\":\"123123 ; passwd -d admin ; passwd -d root ; telnetd\"}"
```

Apoi:

```powershell

```

```text

```


## 7. Alternativă fizică temporară

Pe firmware-ul compatibil, Telnet poate fi activat temporar prin secvența fizică:

```text

```

Apoi:

```powershell
telnet HUB_IP
```

Această metodă este temporară și poate dispărea după reboot sau power cycle.

# PARTEA D – Scriptul persistent complet

## 11. Crearea scriptului

Rulează exact pe hub:

```sh
mkdir -p /data/scripts

cat > /data/scripts/post_init.sh <<'EOF'
#!/bin/sh

# ============================================================
# Aqara Hub M1S persistent startup
#
# 1. Porneste firmware-ul Aqara normal
# 2. Activeaza Telnet dupa conectarea Wi-Fi
# 3. Seteaza Zigbee PA la 0
# 4. Expune MQTT 127.0.0.1:1883 prin portul LAN 1884
# ============================================================

LOG_FILE="/tmp/post_init.log"
MQTT_FIFO="/tmp/aqara_mqtt_pipe"
MQTT_LOCK="/tmp/aqara_mqtt_tunnel.lock"

log_message()
{
    echo "$(date) $1" >> "$LOG_FILE"
}

wait_for_wifi()
{
    i=0

    while [ "$i" -lt 120 ]; do
        IP="$(ifconfig wlan0 2>/dev/null | grep 'inet addr')"

        if [ "$IP" != "" ]; then
            return 0
        fi

        sleep 2
        i=$((i+2))
    done

    return 1
}

wait_for_mqtt()
{
    i=0

    while [ "$i" -lt 120 ]; do
        if netstat -lnt 2>/dev/null | grep -q '127.0.0.1:1883'; then
            return 0
        fi

        sleep 2
        i=$((i+2))
    done

    return 1
}

set_zigbee_pa_zero()
{
    if ! wait_for_mqtt; then
        log_message "MQTT broker not ready; could not set Zigbee PA."
        return 1
    fi

    attempt=1

    while [ "$attempt" -le 10 ]; do
        RESULT="$(zigbee_msnger set_pa 0 2>&1)"
        echo "$RESULT" >> "$LOG_FILE"

        if echo "$RESULT" | grep -q 'zigbee_pa:0'; then
            log_message "Zigbee PA successfully set to 0."
            return 0
        fi

        sleep 3
        attempt=$((attempt+1))
    done

    log_message "Failed to set Zigbee PA to 0."
    return 1
}

start_mqtt_tunnel()
{
    if ! wait_for_mqtt; then
        log_message "MQTT broker not ready; tunnel was not started."
        return 1
    fi

    if ! mkdir "$MQTT_LOCK" 2>/dev/null; then
        log_message "MQTT tunnel already appears to be running."
        return 0
    fi

    log_message "Starting MQTT tunnel on TCP port 1884."

    while true; do
        rm -f "$MQTT_FIFO"

        if ! mkfifo "$MQTT_FIFO"; then
            log_message "Could not create MQTT FIFO; retrying."
            sleep 5
            continue
        fi

        log_message "MQTT tunnel waiting for a client."

        nc -l -p 1884 < "$MQTT_FIFO" |
            nc 127.0.0.1 1883 > "$MQTT_FIFO"

        log_message "MQTT client disconnected; restarting tunnel."

        rm -f "$MQTT_FIFO"
        sleep 1
    done
}

# Pornire normala a sistemului Aqara.
# Aceasta linie este obligatorie.
fw_manager.sh -r &

# Activare Telnet dupa conectarea Wi-Fi.
(
    if wait_for_wifi; then
        sleep 5
        fw_manager.sh -t -k &
        log_message "Telnet enabled after Wi-Fi became available."
    else
        fw_manager.sh -t -k &
        log_message "Wi-Fi timeout; Telnet start attempted anyway."
    fi
) &

# Setare Zigbee PA la 0.
(
    set_zigbee_pa_zero
) &

# Tunel MQTT permanent.
(
    start_mqtt_tunnel
) &

exit 0
EOF

chmod +x /data/scripts/post_init.sh
sync
```

# PARTEA H – Senzorul intern de iluminare

## 22. Topic și payload

Senzorul intern de lumină raportează pe:

```text
zigbee/send
```

Exemplu:

```json
{
  "cmd": "report",
  "id": 2000018442,
  "did": "lumi.0",
  "time": 1783888387968,
  "rssi": 0,
  "zseq": 0,
  "params": [
    {
      "res_name": "0.3.85",
      "value": 50
    }
  ],
  "dev_src": "0"
}
```

Interpretare:

- `did: lumi.0` = hubul;
- `res_name: 0.3.85` = senzorul intern de iluminare;
- `value` = nivelul de lumină raportat.

Configurația:

```text
illCfg : 1200,10
```

Probabil înseamnă:

- raportare periodică la aproximativ 120 secunde;
- raportare la schimbare de aproximativ 10 unități.

Valorile reacționează la întuneric și lanternă, dar pot fi scalate sau filtrate și nu trebuie considerate automat lux calibrați.

# PARTEA K – Securitate

## 25. Avertisment MQTT

Portul `1884` expune brokerul intern fără autentificare.

Nu:

- redirecționa portul în router;
- expune portul în Internet;
- folosi portul pe Wi-Fi public;
- publica interfața prin reverse proxy public.

Recomandat:

- VLAN IoT;
- reguli firewall;
- acces doar din Home Assistant și stații de administrare.

---

## 26. Avertisment Telnet

Telnet nu este criptat.

Datele de autentificare și comenzile pot fi interceptate în rețea.

Folosește-l doar în LAN de încredere.

---

# PARTEA L – Recuperare

## 27. Recuperare prin UART

Dacă hubul nu mai pornește corect pe Wi-Fi:

- adaptor USB-TTL 3.3 V;
- GND → GND;
- TX adaptor → RX hub;
- RX adaptor → TX hub;
- nu conecta VCC;
- viteză: `38400`;
- format: `8N1`;
- flow control: none.

Apoi:

```sh
rm -f /data/scripts/post_init.sh
sync
reboot
```

# PARTEA O – Direcția pentru integrarea Home Assistant

Următoarea versiune a integrării poate folosi:

## MQTT

- abonare la `zigbee/send`;
- senzor iluminare din `res_name: 0.3.85`;
- entitate `light` prin publish pe `ioctl/recv`;
- ascultare evenimente și stări locale.

## Telnet

- redare WAV;
- listare fișiere;
- comenzi încă nemapate în MQTT;
- diagnostic avansat.

## Recomandare arhitecturală

- un singur client MQTT per config entry;
- reconectare automată;
- senzori actualizați push, fără polling;
- Telnet folosit doar când este necesar;
- opțiune separată pentru `set_pa 0`;
- verificare de disponibilitate pentru porturile `23` și `1884`.

---

# Concluzie

Configurația finală păstrează firmware-ul original Aqara și funcțiile importante ale hubului, dar adaugă:

- Telnet/root persistent;
- Zigbee PA setat la `0`;
- tunel MQTT permanent;
- acces la senzorul intern de iluminare;
- control RGB prin MQTT;
- bază pentru o integrare Home Assistant locală mai completă.

Metoda recomandată nu mai oprește `mzigbee_agent` sau `app_monitor.sh`, deoarece acestea sunt necesare pentru mai multe funcții locale ale hubului.
