# Aqara Hub M1S – Persistent Telnet, Zigbee PA 0, and Permanent MQTT Tunnel

## 1. Purpose

This procedure configures an Aqara Hub M1S so that, after every reboot:

- the original Aqara firmware starts normally;
- Wi-Fi, HomeKit, and local services remain functional;
- Telnet/root is enabled automatically;
- the Zigbee Power Amplifier parameter is automatically set to `0`;
- the internal MQTT broker on `127.0.0.1:1883` is exposed on the LAN through port `1884`;
- the MQTT tunnel automatically restarts after the client disconnects;
- important local functions, including the light, audio, and illuminance sensor, remain active.

No modified firmware is required, and nothing is written to the root filesystem.

---

## 2. Tested configuration

- Device: Aqara Hub M1S
- Model: `lumi.gateway.aeu01`
- Firmware: `3.1.3_0009`
- Kernel: Linux 3.10.90, MIPS
- Zigbee chip: NXP JN5189
- Zigbee interface: `/dev/ttyS1`
- Internal MQTT broker: `127.0.0.1:1883`
- MQTT port exposed on LAN: `1884`
- Zigbee service: `mzigbee_agent`
- Service monitor: `app_monitor.sh`

---

## 3. Important warnings

1. Do not modify `/etc/init.d/rcS`.
2. Do not modify `/bin/fw_manager.sh`.
3. Do not use `telnetd -l /bin/sh` as the permanent method.
4. The `/data/scripts/post_init.sh` script must always start:
   ```sh
   fw_manager.sh -r &
   ```
5. Do not stop:
   - `mha_basis`
   - `mha_master`
   - `homekitserver`
   - `miio_client`
   - `mzigbee_agent`
   - `app_monitor.sh`
6. Do not expose port `1884` to the Internet.
7. Telnet and MQTT are unencrypted and should only be used on a trusted local network.
8. Ideally, perform the first test with UART access available for recovery.

---

## 4. Why `mzigbee_agent` should no longer be stopped

The old method stopped:

```sh
killall app_monitor.sh
killall mzigbee_agent
```

This is no longer recommended.

Reason: `mzigbee_agent` does not manage only the Zigbee radio. Based on testing, it also participates in local hub functions, including:

- LED control;
- reporting from the internal illuminance sensor;
- internal MQTT communication;
- other hub-related features.

Stopping the process completely can break light control and other local functions.

The new method keeps the services active and runs only:

```sh
zigbee_msnger set_pa 0
```

This sets the Power Amplifier parameter to `0` without stopping the entire Zigbee service.

Important: `zigbee_pa:0` does not prove that the entire JN5189 radio is fully powered down. It only confirms that the PA parameter is `0`, which disables or reduces the external RF amplifier.

# PART A – Initial Telnet/root activation

## 5. Obtain the IP address and MiIO token

You need:

- the hub IP address;
- the MiIO token.

Example:

```text
IP: 192.168.0.100
Token: 6134744347534874785067434exxxxxx
```

In Windows PowerShell:

```powershell
python -m miio.cli device --ip 192.168.0.100 --token TOKEN info
```

If the model and firmware version are displayed, the token is valid.

---

## 6. Temporarily enable Telnet/root through MiIO

In Windows PowerShell or CMD:

```powershell
python -m miio.cli device --ip 192.168.0.100 --token TOKEN raw_command set_ip_info "{"ssid":"\"\"","pswd":"123123 ; passwd -d admin ; passwd -d root ; telnetd"}"
```

Then:

```powershell
telnet 192.168.0.100
```

Login:

```text
Login: admin
Password: press Enter
```

If that does not work:

```text
Login: root
Password: press Enter
```

---

## 7. Temporary physical alternative

On compatible firmware, Telnet can also be enabled temporarily using the physical sequence:

```text
5-2-2-2-2-2-2
```

Then:

```powershell
telnet HUB_IP
```

This method is temporary and may disappear after a reboot or power cycle.

# PART D – Create the permanent MQTT tunnel and startup scripts

## 11. Create `/data/scripts/mqtt_tunnel.sh`

The tested tunnel uses a separate self-restarting script:

```sh
cat > /data/scripts/mqtt_tunnel.sh <<'EOF'
#!/bin/sh

LOG_FILE="/tmp/post_init.log"
MQTT_FIFO="/tmp/aqara_mqtt_pipe"

while true; do
    while ! netstat -lnt 2>/dev/null | grep -q '127.0.0.1:1883'; do
        sleep 2
    done

    killall nc 2>/dev/null
    rm -f "$MQTT_FIFO"
    mkfifo "$MQTT_FIFO"

    echo "$(date) MQTT tunnel waiting for a client." >> "$LOG_FILE"

    cat "$MQTT_FIFO" |
        nc -l -p 1884 |
        nc 127.0.0.1 1883 > "$MQTT_FIFO"

    echo "$(date) MQTT client disconnected; restarting tunnel." >> "$LOG_FILE"

    rm -f "$MQTT_FIFO"
    sleep 1
done
EOF

chmod +x /data/scripts/mqtt_tunnel.sh
sync
```

This BusyBox `nc` tunnel accepts one active client at a time and recreates itself after disconnection.

## 12. Create `/data/scripts/post_init.sh`

```sh
mkdir -p /data/scripts

cat > /data/scripts/post_init.sh <<'EOF'
#!/bin/sh

LOG_FILE="/tmp/post_init.log"

log_message()
{
    echo "$(date) $1" >> "$LOG_FILE"
}

wait_for_wifi()
{
    i=0

    while [ "$i" -lt 120 ]; do
        IP="$(ifconfig wlan0 2>/dev/null | grep 'inet addr')"

        if [ "$IP" != "" ]; then
            return 0
        fi

        sleep 2
        i=$((i+2))
    done

    return 1
}

wait_for_mqtt()
{
    i=0

    while [ "$i" -lt 120 ]; do
        if netstat -lnt 2>/dev/null | grep -q '127.0.0.1:1883'; then
            return 0
        fi

        sleep 2
        i=$((i+2))
    done

    return 1
}

set_zigbee_pa_zero()
{
    if ! wait_for_mqtt; then
        log_message "MQTT broker not ready; could not set Zigbee PA."
        return 1
    fi

    attempt=1

    while [ "$attempt" -le 10 ]; do
        RESULT="$(zigbee_msnger set_pa 0 2>&1)"
        echo "$RESULT" >> "$LOG_FILE"

        if echo "$RESULT" | grep -q 'zigbee_pa:0'; then
            log_message "Zigbee PA successfully set to 0."
            return 0
        fi

        sleep 3
        attempt=$((attempt+1))
    done

    log_message "Failed to set Zigbee PA to 0."
    return 1
}

# Mandatory: start the original Aqara firmware.
fw_manager.sh -r &

# Enable Telnet after Wi-Fi becomes available.
(
    if wait_for_wifi; then
        sleep 5
        fw_manager.sh -t -k &
        log_message "Telnet enabled after Wi-Fi became available."
    else
        fw_manager.sh -t -k &
        log_message "Wi-Fi timeout; Telnet start attempted anyway."
    fi
) &

# Set Zigbee PA to 0.
(
    set_zigbee_pa_zero
) &

# Start the self-restarting MQTT tunnel.
(
    /data/scripts/mqtt_tunnel.sh
) &

exit 0
EOF

chmod +x /data/scripts/post_init.sh
sync
```

## 19. Check the MQTT tunnel

Check the processes:

```sh
ps w | grep -e mqtt_tunnel -e 'nc -l'
```

When no client is connected:

```sh
netstat -lntp 2>/dev/null | grep 1884
```

When a client is already connected, BusyBox `nc` may no longer appear in `LISTEN`. Check the kernel TCP table instead:

```sh
grep -i ':075C' /proc/net/tcp /proc/net/tcp6
```

`075C` is port `1884` in hexadecimal.

- state `0A` = LISTEN
- state `01` = ESTABLISHED

From Windows:

```powershell
Test-NetConnection HUB_IP -Port 1884
```

Expected result:

```text
TcpTestSucceeded : True
```

The BusyBox `nc` tunnel accepts one client at a time, but the script automatically restarts it after the client disconnects.

# PART H – Internal illuminance sensor

## 22. Topic and payload

The internal light sensor reports on:

```text
zigbee/send
```

Example:

```json
{
  "cmd": "report",
  "id": 2000018442,
  "did": "lumi.0",
  "time": 1783888387968,
  "rssi": 0,
  "zseq": 0,
  "params": [
    {
      "res_name": "0.3.85",
      "value": 50
    }
  ],
  "dev_src": "0"
}
```

Interpretation:

- `did: lumi.0` = the hub itself;
- `res_name: 0.3.85` = the internal illuminance sensor;
- `value` = reported light level.

Configuration:

```text
illCfg : 1200,10
```

This probably means:

- periodic reporting approximately every 120 seconds;
- reporting on a change of approximately 10 units.

The values react to darkness and flashlight exposure, but may be scaled or filtered and should not automatically be treated as calibrated lux.

# PART K – Security

## 25. MQTT warning

Port `1884` exposes the internal broker without authentication.

Do not:

- forward the port in the router;
- expose the port to the Internet;
- use it on public Wi-Fi;
- publish the interface through a public reverse proxy.

Recommended:

- IoT VLAN;
- firewall rules;
- access only from Home Assistant and trusted administration devices.

---

## 26. Telnet warning

Telnet is not encrypted.

Credentials and commands can be intercepted on the network.

Use it only on a trusted LAN.

# PART L – Recovery

## 27. Recovery through UART

If the hub no longer starts correctly on Wi-Fi:

- USB-TTL adapter: 3.3 V;
- GND → GND;
- adapter TX → hub RX;
- adapter RX → hub TX;
- do not connect VCC;
- speed: `38400`;
- format: `8N1`;
- flow control: none.

Then:

```sh
rm -f /data/scripts/post_init.sh
rm -f /data/scripts/mqtt_tunnel.sh
sync
reboot
```

# PART O – Direction for the Home Assistant integration

The next version of the integration can use:

## MQTT

- subscribe to `zigbee/send`;
- create an illuminance sensor from `res_name: 0.3.85`;
- create a `light` entity by publishing to `ioctl/recv`;
- listen for local events and states.

## Telnet

- WAV playback;
- file listing;
- commands not yet mapped to MQTT;
- advanced diagnostics.

## Architectural recommendation

- one MQTT client per config entry;
- automatic reconnect;
- push-based sensor updates, without polling;
- Telnet only when required;
- a separate option for `set_pa 0`;
- availability checks for ports `23` and `1884`.

---

# Conclusion

The final configuration preserves the original Aqara firmware and the hub's important functions while adding:

- persistent Telnet/root;
- Zigbee PA set to `0`;
- a permanent MQTT tunnel;
- access to the internal illuminance sensor;
- RGB control through MQTT;
- a foundation for a more complete local Home Assistant integration.

The recommended method no longer stops `mzigbee_agent` or `app_monitor.sh`, because they are required for several local hub functions.
