# Aqara Hub M1S – Telnet persistent, Zigbee PA 0 și tunel MQTT permanent

## 1. Scop

Această procedură configurează un Aqara Hub M1S astfel încât, după fiecare repornire:

- firmware-ul original Aqara să pornească normal;
- Wi-Fi, HomeKit și serviciile locale să rămână funcționale;
- Telnet/root să fie activat automat;
- parametrul Zigbee Power Amplifier să fie setat automat la `0`;
- brokerul MQTT intern de pe `127.0.0.1:1883` să fie expus în LAN prin portul `1884`;
- tunelul MQTT să se repornească automat după deconectarea clientului;
- funcțiile locale importante, inclusiv lumina, sunetul și senzorul de iluminare, să rămână active.

Nu este necesar firmware modificat și nu se modifică niciun fișier din root filesystem.

---

## 2. Configurație testată

- Dispozitiv: Aqara Hub M1S
- Model: `lumi.gateway.aeu01`
- Firmware: `3.1.3_0009`
- Kernel: Linux 3.10.90, MIPS
- BusyBox: 1.22.1
- Cip Zigbee: NXP JN5189
- UART Zigbee: `/dev/ttyS1`
- Broker MQTT intern: `127.0.0.1:1883`
- Port tunel MQTT: `1884`
- Serviciu Zigbee: `mzigbee_agent`
- Proces audio principal: `mha_basis`
- Monitor servicii: `app_monitor.sh`

---

## 3. Avertismente importante

1. Nu modifica `/etc/init.d/rcS`.
2. Nu modifica `/bin/fw_manager.sh`.
3. Nu folosi `telnetd -l /bin/sh` ca metodă permanentă.
4. `/data/scripts/post_init.sh` trebuie să pornească întotdeauna:
   ```sh
   fw_manager.sh -r &
   ```
5. Nu opri:
   - `mha_basis`
   - `mha_master`
   - `homekitserver`
   - `miio_client`
   - `mzigbee_agent`
   - `app_monitor.sh`
6. Nu expune portul `1884` pe Internet.
7. Telnet și acest tunel MQTT sunt necriptate și trebuie folosite doar într-un LAN de încredere.
8. Ideal, păstrează accesul UART disponibil la primele teste de reboot și power cycle.

---

## 4. De ce `mzigbee_agent` trebuie să rămână activ

O metodă mai veche oprea:

```sh
killall app_monitor.sh
killall mzigbee_agent
```

Acea metodă nu mai este recomandată.

Testele au arătat că `mzigbee_agent` nu este responsabil doar de comunicația Zigbee. El participă și la funcții locale ale hubului, inclusiv:

- controlul LED-ului;
- raportarea iluminării interne;
- comunicația MQTT internă;
- alte comportamente locale ale hubului.

Oprirea lui poate dezactiva controlul luminii și alte funcții locale.

Metoda actuală păstrează procesul activ și execută doar:

```sh
zigbee_msnger set_pa 0
```

Aceasta setează parametrul Zigbee Power Amplifier la `0`.

Important: `zigbee_pa:0` nu demonstrează că întregul radio JN5189 este complet oprit. Confirmă doar că setarea PA este `0`, ceea ce dezactivează sau reduce amplificatorul RF extern.

# PARTEA A – Activarea inițială Telnet/root

## 5. Obținerea IP-ului hubului și a tokenului MiIO

Ai nevoie de:

- adresa IP a hubului;
- tokenul MiIO.

Exemplu:

```text
IP: 192.168.0.100
Token: 6134744347534874785067434exxxxxx
```

Verifică tokenul din Windows PowerShell:

```powershell
python -m miio.cli device --ip 192.168.0.100 --token TOKEN info
```

Dacă sunt returnate modelul și firmware-ul, tokenul este valid.

---

## 6. Activarea temporară Telnet/root prin MiIO

Rulează din Windows PowerShell sau CMD:

```powershell
python -m miio.cli device --ip 192.168.0.100 --token TOKEN raw_command set_ip_info "{"ssid":"\"\"","pswd":"123123 ; passwd -d admin ; passwd -d root ; telnetd"}"
```

Apoi conectează-te:

```powershell
telnet 192.168.0.100
```

Încearcă:

```text
Login: admin
Password: apasă Enter
```

Dacă nu funcționează:

```text
Login: root
Password: apasă Enter
```

---

## 7. Alternativă fizică temporară

Pe firmware compatibil, Telnet/root poate fi activat temporar folosind secvența fizică de butoane:

```text
5-2-2-2-2-2-2
```

Apoi:

```powershell
telnet HUB_IP
```

Această metodă poate dispărea după reboot sau power cycle.

# PARTEA D – Crearea tunelului MQTT permanent și a scriptului de pornire

## 11. Creează `/data/scripts/mqtt_tunnel.sh`

Rulează exact pe hub:

```sh
cat > /data/scripts/mqtt_tunnel.sh <<'EOF'
#!/bin/sh

LOG_FILE="/tmp/post_init.log"
MQTT_FIFO="/tmp/aqara_mqtt_pipe"

while true; do
    while ! netstat -lnt 2>/dev/null | grep -q '127.0.0.1:1883'; do
        sleep 2
    done

    killall nc 2>/dev/null
    rm -f "$MQTT_FIFO"
    mkfifo "$MQTT_FIFO"

    echo "$(date) MQTT tunnel waiting for a client." >> "$LOG_FILE"

    cat "$MQTT_FIFO" |
        nc -l -p 1884 |
        nc 127.0.0.1 1883 > "$MQTT_FIFO"

    echo "$(date) MQTT client disconnected; restarting tunnel." >> "$LOG_FILE"

    rm -f "$MQTT_FIFO"
    sleep 1
done
EOF

chmod +x /data/scripts/mqtt_tunnel.sh
sync
```

Acest tunel BusyBox `nc` acceptă un singur client activ simultan și se recreează după deconectare.

## 12. Creează `/data/scripts/post_init.sh`

```sh
mkdir -p /data/scripts

cat > /data/scripts/post_init.sh <<'EOF'
#!/bin/sh

LOG_FILE="/tmp/post_init.log"

log_message()
{
    echo "$(date) $1" >> "$LOG_FILE"
}

wait_for_wifi()
{
    i=0

    while [ "$i" -lt 120 ]; do
        IP="$(ifconfig wlan0 2>/dev/null | grep 'inet addr')"

        if [ "$IP" != "" ]; then
            return 0
        fi

        sleep 2
        i=$((i+2))
    done

    return 1
}

wait_for_mqtt()
{
    i=0

    while [ "$i" -lt 120 ]; do
        if netstat -lnt 2>/dev/null | grep -q '127.0.0.1:1883'; then
            return 0
        fi

        sleep 2
        i=$((i+2))
    done

    return 1
}

set_zigbee_pa_zero()
{
    if ! wait_for_mqtt; then
        log_message "MQTT broker not ready; could not set Zigbee PA."
        return 1
    fi

    attempt=1

    while [ "$attempt" -le 10 ]; do
        RESULT="$(zigbee_msnger set_pa 0 2>&1)"
        echo "$RESULT" >> "$LOG_FILE"

        if echo "$RESULT" | grep -q 'zigbee_pa:0'; then
            log_message "Zigbee PA successfully set to 0."
            return 0
        fi

        sleep 3
        attempt=$((attempt+1))
    done

    log_message "Failed to set Zigbee PA to 0."
    return 1
}

# Obligatoriu: porneste firmware-ul original Aqara.
fw_manager.sh -r &

# Activeaza Telnet dupa ce Wi-Fi devine disponibil.
(
    if wait_for_wifi; then
        sleep 5
        fw_manager.sh -t -k &
        log_message "Telnet enabled after Wi-Fi became available."
    else
        fw_manager.sh -t -k &
        log_message "Wi-Fi timeout; Telnet start attempted anyway."
    fi
) &

# Seteaza Zigbee PA la 0.
(
    set_zigbee_pa_zero
) &

# Porneste tunelul MQTT cu autorepornire.
(
    /data/scripts/mqtt_tunnel.sh
) &

exit 0
EOF

chmod +x /data/scripts/post_init.sh
sync
```

## 20. Verificarea tunelului MQTT

Când nu este conectat niciun client:

```sh
netstat -lntp 2>/dev/null | grep 1884
```

Ar trebui în mod normal să vezi un listener pe portul `1884`.

Când un client este deja conectat, listener-ul poate să nu mai apară deoarece BusyBox `nc` gestionează un singur client activ. În acest caz folosește:

```sh
grep -i ':075C' /proc/net/tcp /proc/net/tcp6
```

`075C` este portul `1884` în hexazecimal.

Stări TCP relevante:

- `0A` = LISTEN
- `01` = ESTABLISHED

Exemplu de conexiune activă confirmată:

```text
...:075C ... 01 ...
```

Din Windows:

```powershell
Test-NetConnection HUB_IP -Port 1884
```

Important: acest test deschide el însuși singura conexiune disponibilă și poate consuma temporar listener-ul. Scriptul tunelului ar trebui să îl recreeze după deconectare.

# PARTEA H – Senzorul intern de iluminare

## 23. Resursa MQTT

Senzorul intern de lumină raportează pe:

```text
Topic: zigbee/send
```

Exemplu:

```json
{
  "cmd": "report",
  "did": "lumi.0",
  "params": [
    {
      "res_name": "0.3.85",
      "value": 50
    }
  ]
}
```

Interpretare:

- `did: lumi.0` = hubul însuși;
- `res_name: 0.3.85` = resursa internă de iluminare;
- `value` = nivelul de lumină raportat.

Configurația conține:

```text
illCfg : 1200,10
```

Probabil reprezintă:

- raportare periodică aproximativ la 120 secunde;
- raportare când valoarea se schimbă cu aproximativ 10 unități.

Valorile reacționează la întuneric și lanternă, dar pot fi scalate sau filtrate, nu neapărat lux calibrați.

# PARTEA I – Controlul luminii RGB prin MQTT

## 24. Topic MQTT

```text
ioctl/recv
```

Exemplu payload:

```json
{
  "cmd": "control",
  "data": {
    "blue": 80,
    "breath": 500,
    "green": 105,
    "red": 245
  },
  "id": 50001,
  "type": "rgb",
  "ver": 1
}
```

Test de publish:

```powershell
python -c "import json,time,paho.mqtt.client as mqtt; c=mqtt.Client(mqtt.CallbackAPIVersion.VERSION2); c.connect('HUB_IP',1884); c.loop_start(); c.publish('ioctl/recv',json.dumps({'cmd':'control','data':{'blue':80,'breath':500,'green':105,'red':245},'id':50001,'type':'rgb','ver':1})).wait_for_publish(); time.sleep(1); c.disconnect(); c.loop_stop()"
```

S-a confirmat că această comandă schimbă culoarea LED-ului hubului.

Mesajele de comportament RGB observate includ și:

```text
ioctl/recv {"cmd":"behave", ...}
ioctl/send {"cmd":"behaved", ...}
```

Acestea sunt folosite pentru animații LED temporare și confirmări.

## 27. Starea actuală a investigației audio

Confirmat:

- redarea WAV directă prin `aplay` funcționează;
- redarea oficială Aqara este făcută de `mha_basis`;
- fișierele WAV oficiale sunt citite din `/data/musics/...`;
- traficul RGB și de iluminare este vizibil prin MQTT.

Încă neconfirmat:

- calea comenzii care solicită redarea oficială a unui sunet;
- comanda de control al volumului;
- un topic sau payload MQTT pentru control audio.

Schimbarea volumului oficial poate genera mesaje de feedback RGB, dar acestea nu trebuie tratate drept comanda audio reală.

Arhitectura recomandată momentan:

- MQTT pentru stare, evenimente, iluminare și RGB;
- Telnet pentru redare WAV și comenzi încă nemapate în MQTT.

# PARTEA K – Securitate

## 28. Avertisment pentru tunelul MQTT

Portul `1884` expune brokerul MQTT intern fără autentificare.

Nu:

- redirecționa portul `1884` prin router;
- expune portul pe Internet;
- publica portul prin reverse proxy public;
- folosi portul într-o rețea Wi-Fi neîncredere.

Recomandat:

- VLAN IoT;
- reguli firewall;
- acces doar din Home Assistant și dispozitive de administrare de încredere.

---

## 29. Avertisment Telnet

Telnet este necriptat.

Folosește-l doar într-un LAN de încredere.

# PARTEA L – Recuperare

## 30. Recuperare prin UART

Parametri UART:

- adaptor USB-TTL: 3.3 V;
- GND → GND;
- TX adaptor → RX hub;
- RX adaptor → TX hub;
- nu conecta VCC;
- viteză: `38400`;
- format: `8N1`;
- flow control: none.

Pentru eliminarea tuturor modificărilor persistente:

```sh

sync
```

# PARTEA O – Direcția pentru integrarea Home Assistant

Următoarea versiune a integrării poate folosi:

## MQTT

- abonare la `zigbee/send`;
- creare senzor de iluminare din `res_name: 0.3.85`;
- creare entitate nativă `light` prin publish pe `ioctl/recv`;
- primire evenimente și stări locale;
- actualizări push în loc de polling.

## Telnet

- redare WAV;
- descoperire fișiere;
- comenzi încă nemapate în MQTT;
- diagnostic.

## Arhitectură recomandată

- un client MQTT per config entry;
- reconectare automată;
- verificări de disponibilitate pentru porturile `23` și `1884`;
- MQTT pentru stări push;
- Telnet doar când este necesar;
- opțiune de configurare pentru Zigbee PA 0;
- fără clienți MQTT dublați pentru același hub.

---

# Concluzie

Configurația testată păstrează firmware-ul original Aqara și funcțiile locale ale hubului, adăugând:

- Telnet/root persistent;
- Zigbee PA setat la `0`;
- tunel MQTT cu autorepornire;
- acces la senzorul intern de iluminare;
- control RGB local prin MQTT;
- identificarea confirmată a lui `mha_basis` ca proces oficial de redare audio;
- o bază pentru o integrare Home Assistant locală mai completă.

Metoda recomandată nu mai oprește `mzigbee_agent` sau `app_monitor.sh`, deoarece ambele sunt necesare pentru funcții locale importante ale hubului.
